In this section, we will discuss how it was possible to perform \textit{slicing} of the network in order to differentiate the treatment of different flows. In this particular case, exploiting the same logical view of the network used in the previous section, we ensure that the lower \textit{slice} is intended for normal traffic and the connection of all hosts to each other, while the upper \textit{slice} is intended for video traffic.
To perform this separation, filters are implemented on switches s1 and s2. Switch s3 checks that the flow is actually of \textit{streaming video} type (UDP port 9999), while switch s4 handles all other traffic through bidirectional forwarding.
No modifications were made to the topology through Mininet, so the changes to the Ryu controller class are presented below.

\vspace{.3cm}

\begin{pythoncode}
@set_ev_cls(ofp_event.EventOFPSwitchFeatures, CONFIG_DISPATCHER)
def switch_features_handler(self, ev):
    datapath = ev.msg.datapath
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser
    dpid = datapath.id
    self.logger.info(f"[FEATURES HANDLER] dpid={dpid}")
    if dpid == 1: # If switch s1, if the packet from the host is UDP on port 9999, send it to the upper path.
        port_up, port_dw = 3, 4 
        port_h1, port_h2 = 1, 2
        for host_port in [port_h1, port_h2]:
            match = parser.OFPMatch(
                in_port=host_port,
                eth_type=0x0800,
                ip_proto=17,
                udp_dst=UDP_PORT_STREAMING
            )
            actions = [parser.OFPActionOutput(port_up)]
            self.add_flow(datapath, priority=100, match=match, actions=actions)
    elif dpid == 2: # For switch s2, if the packet from the host is UDP on port 9999, send it to the upper path.
        port_up, port_dw = 1, 2
        port_h3, port_h4 = 3, 4
        for host_port in [port_h3, port_h4]:
            match = parser.OFPMatch(
                in_port=host_port,
                eth_type=0x0800,
                ip_proto=17,
                udp_dst=UDP_PORT_STREAMING
            )
            actions = [parser.OFPActionOutput(port_up)]
            self.add_flow(datapath, priority=100, match=match, actions=actions)
    elif dpid == 3: # For switch s3, if the packet is UDP on port 9999, let it pass.
        match = parser.OFPMatch(
            in_port=1, eth_type=0x0800, ip_proto=17, udp_dst=UDP_PORT_STREAMING
        )
        actions = [parser.OFPActionOutput(2)]
        self.add_flow(datapath, priority=100, match=match, actions=actions)
        match = parser.OFPMatch(
            in_port=2, eth_type=0x0800, ip_proto=17, udp_dst=UDP_PORT_STREAMING
        )
        actions = [parser.OFPActionOutput(1)]
        self.add_flow(datapath, priority=100, match=match, actions=actions)
    elif dpid == 4: # For switch s4, forward all packets bidirectionally.
        match = parser.OFPMatch(in_port=1)
        actions = [parser.OFPActionOutput(2)]
        self.add_flow(datapath, priority=1, match=match, actions=actions)
        match = parser.OFPMatch(in_port=2)
        actions = [parser.OFPActionOutput(1)]
        self.add_flow(datapath, priority=1, match=match, actions=actions)
    # default rule -> sends packet to controller
    match = parser.OFPMatch()
    actions = [parser.OFPActionOutput(ofproto.OFPP_CONTROLLER,
                                    ofproto.OFPCML_NO_BUFFER)]
    self.add_flow(datapath, priority=0, match=match, actions=actions)
\end{pythoncode}
\newpage



The implemented strategy combines two complementary approaches: the proactive rules installed in the \textit{switch features handler} and reactive management through the \textit{packet in handler}. Proactive rules ensure that video streaming traffic (UDP port 9999) is always routed on the dedicated upper path without involving the controller for each packet. Conversely, reactive management intervenes when no matching rule exists: the packet is forwarded to the controller, which extracts information from the packet header, updates its MAC tables, and decides the optimal path. This hybrid approach reduces latency for critical traffic (video streaming) through proactive rules, while reactive management provides flexibility and adaptability for best effort traffic, thus avoiding overloading the controller with already-classified packets.

Service-based forwarding is evident in the instructions concerning packet matching on edge switches, where the rule is defined such that if the packet uses the IP/UDP protocol on port 9999 (video streaming), it is always sent on the upper path, regardless of the MAC addresses of the communicating devices. Switches s3 and s4, on the other hand, are only responsible for bidirectional forwarding in case of a match (IP/UDP on port 9999 for switch s3 and all other packets for switch s4).

\begin{pythoncode}
@set_ev_cls(ofp_event.EventOFPPacketIn, MAIN_DISPATCHER)
def _packet_in_handler(self, ev):
    msg = ev.msg
    datapath = msg.datapath
    ofproto = datapath.ofproto
    parser = datapath.ofproto_parser
    dpid = datapath.id
    in_port = msg.match['in_port'] # port from which the packet was received

    pkt = packet.Packet(msg.data)
    eth = pkt.get_protocol(ethernet.ethernet)
    if eth is None:
        return
    dst = eth.dst
    src = eth.src
    self.mac_to_port.setdefault(dpid, {})

    self.mac_to_port[dpid][src] = in_port # update MAC table with the source MAC and the port it came from

    # known destination mac 
    if dst in self.mac_to_port[dpid]: 
        out_port = self.mac_to_port[dpid][dst] # get the port to which the destination MAC is associated
        actions = [parser.OFPActionOutput(out_port)] # create an action to forward the packet to the correct port

    # unknown destination mac -> flood only on the down path
    else:
        host_ports = {
            1: {1,2}, 
            2: {3,4}, 
            3: set(), 
            4: set() 
        }

        interswitch_links = {
            1: {4}, # [dpid] -> down path 
            2: {2},
        }

        actions = []
        for p in host_ports.get(dpid, set()):
            if p != in_port:
                actions.append(parser.OFPActionOutput(p))

        for p in interswitch_links.get(dpid, set()):
            if p != in_port:
                actions.append(parser.OFPActionOutput(p))

    if len(actions) == 1: # if there is only one action, it means we have a known destination and we can install a flow rule for future packets
        match = parser.OFPMatch(in_port=in_port, eth_src=src, eth_dst=dst)
        self.add_flow(datapath, priority=1, match=match, actions=actions)

    out = parser.OFPPacketOut(
        datapath=datapath,
        buffer_id=msg.buffer_id,
        in_port=in_port,
        actions=actions,
        data=msg.data
    )
    datapath.send_msg(out)
\end{pythoncode}

\noindent 
This function is called every time a switch receives a packet, finds no match, and forwards the packet to the controller.
The controller extracts information from the packet and maintains a MAC table for each switch, where the association (MAC, port) is found.
If the destination is already known, it is used for direct forwarding. If the destination is unknown, the packet is flooded only on the down route.
Then the flow rule is installed on the switch to handle future packets with the same source and destination MAC addresses.
